# 家庭财务全景

静态财务仪表盘，无统计追踪。首次访问为空；默认在浏览器保存，支持主动启用 Supabase 私有云同步。个人财务数据不进入 GitHub。

## 使用

日常入口为「总览、账本、我的」。点击「更新数据」选择导入账本、更新余额或恢复完整备份。手机使用固定底部导航；账户、股权、核实及历史进入详情页，备份在「我的」。登录并启用同步后，可以在不同设备更新同一份数据。

- **总览**：金融净额、现金与理财扣除短债、股票市值及其占已知金融资产的比例。家庭其他资产负债单独呈现，未知值不会默认为零；待归属股票不计入当前净额。
- **账户与对账**：填写真实余额与对应时间，资产和负债均填正数。账户余额是汇总的唯一计算来源，更新账户即更新首页。旧版分类余额自动迁移为汇总账户，原对账基准保留但不重复计入总额。可将已知汇总拆为明细账户，明细合计必须与当前汇总相等；确认全部为同一时点的实际余额后保存。
- **账本与现金流**：导入挖财 `.xlsx`，预览覆盖期、相同/加入/移除笔数和金融净额影响后确认替换。重复导入不累加。年度工资奖金与月度账面收入、支出分开展示；账面差额不等于真实消费、储蓄或家庭结余。
- **核实与事件**：保存结论、来源、状态及交易关联。只有已确认、用途明确且唯一匹配的记录参与资金用途汇总。原账变化、重复匹配或冲突会暂停归类，保留说明供重新关联；不会自动修改原账。
- **股权**：行情、手动价格及待归属情景。情景须明确填写认购成本和税费，空白表示未知；情景不改变当前资产。现金与理财合计不代表全部可即时支取。
- **资产历史**：记录当时余额、股价、净额和未知状态，之后行情不会重算旧历史。不从流水倒推旧资产，最多保存 500 条。

## 账本与余额推算

支持挖财实际导出的前置信息行及日期时间、类型、类别、金额、币种表头；账户推算还需要收付账户和完整交易时间。只支持人民币，未知类型、异常日期或金额会拒绝导入并保留旧数据。最多 100,000 笔、30 MB，实际受浏览器存储容量限制；多个明细表需先保留一个。

在「设置账本自动调整」明确确认账户分类后启用。每次从各账户保存的余额与时间重新处理之后的记录，收入、支出、转账按账户方向计算；信用卡还款同时减少现金和负债，不计为消费。基准之前的历史修订不改写已确认余额。必须使用覆盖基准日至今的完整账本。

缺少时间、未知账户、起始余额未知、借贷、股票交易、转账不配平或余额为负等情况，会暂停整个汇总推算并回到各账户基准，避免显示部分更新的总额。基准可能来自不同日期，应查看账户表核实。账本漏记、理财价格变化、股票数量变化仍须人工确认；显示的是账本推算，不是银行实时余额。

工资类别为收入中的「工资薪水、工资收入、加班收入」，奖金为「奖金」；有层级时取末级类别。公积金、福利、股票、退款、转账、借贷和余额调整不计入工资奖金。金额以整数分计算，保留负数修正。

## 本地保存与备份

完整数据使用 `localStorage`；未启用私有同步时，不同设备、浏览器或网址不自动同步。清理浏览器数据会删除账本，隐私模式可能不保留。保存失败提示原因并保留原状态。

定期导出 JSON 明文备份；恢复前严格校验并确认覆盖。格式版本为 v4，兼容 v1–v3，包含账本、余额、股价、账户设置、核实记录、情景及历史。金额以整数分保存。备份含个人信息，不应提交到仓库或公开分享。

每次成功导入前，将上次账本保存为本浏览器的恢复点，可撤销最近一次导入。恢复点使用 IndexedDB，不随备份导出，不改变账户、核实记录和历史；清空或恢复备份会删除恢复点。无法保存恢复点则取消导入。完整账本仍使用 localStorage。

## 行情与隐私

金山办公 `688111` 的东方财富公开行情在页面可见时每 60 秒刷新，显示行情自身时间，休市可能为最近交易日。失败保留旧价，可手动输入；手动模式不被自动覆盖，可恢复自动模式。公共接口没有可用性承诺。

Excel 在浏览器本地解析，仅保留统计和核对需要的日期、类型、类别、金额、币种、账户及交易时间，不保存原文件或收付款人。账本、余额、事件、备份不上传。唯一外部请求是固定股票代码的行情，不含个人数据，不带凭据或页面来源。

SheetJS CE 0.20.3 随站点发布，不运行第三方加载脚本；[官方文档](https://docs.sheetjs.com/docs/getting-started/installation/standalone/)，许可见 `vendor/LICENSE.sheetjs`。同一 GitHub Pages 域名下其他站点共享浏览器来源，仅在可信域名使用。

## 验证与部署

本地预览：`python3 -m http.server 8765 --bind 127.0.0.1`，通过 HTTP(S) 打开，避免文件预览。

验证：`node --test tests/core.test.cjs`。测试均为虚构数据，涵盖格式迁移、账户汇总、转账、拆分、未知值、股权情景、核实关联和账本替换。

主分支 `main` 使用 GitHub Actions 自动部署。工作流运行验证后，仅打包明确列出的 `index.html / styles.css / core.js / app.js / favicon.svg` 及两份依赖文件，资源使用相对路径和内容版本标识。无需服务器或秘密变量。

不要使用 `git add .` 上传财务目录。原始账单、截图、私人备份和真实测试文件排除在提交之外；公开代码不包含个人金额、持仓、交易或家庭事件。


## Supabase 私有同步

网页代码和 Publishable key 可以公开；数据库密码、Secret/service-role 密钥不能进入网页或仓库。`supabase/setup.sql` 仅为无真实邮箱的部署模板，在 SQL Editor 中执行前应核对现有表，私下填写本人邮箱。先创建访问规则，再验证匿名访问和非本人账号被拒绝，最后连接真实数据。仅通过验证邮箱的本人账号能够读取其数据。网页没有数据库管理权限。

在「我的」点击「邮箱登录」，使用项目成员邮箱接收登录链接，并在同一设备、同一浏览器打开。默认邮件服务受 Supabase 的发送限制和送达可靠性约束，不额外注册邮件服务。登录后仍需明确启用自动同步，才将解析后的交易、账户、核实记录、历史和手动股价设置保存至私人数据库；原始 Excel 不上传。自动行情保留在当前设备，不触发云写入。

前台每 15 秒检查新版本，离线保存本机数据并在联网后重试。两台设备均有改动时暂停自动覆盖；选择版本前先导出本机备份。服务器只允许通过校验版本的函数更新，保留最近 10 个旧版本供管理员恢复；仍应定期导出独立备份。退出登录保留本机数据，清空本机数据会暂停同步，不删除云端。默认在浏览器持久保存登录状态，共用设备请退出登录。

数据使用 HTTPS 传输，数据库管理者仍可读取存储内容，不是端到端加密。压缩内容限 1.5 MB，解压后限 25 MB，超限保留本机数据并提示。浏览器需支持 CompressionStream/DecompressionStream。Supabase 客户端依赖已打包在 `vendor/`，不从第三方 CDN 动态加载。
